# P20 轻量化运行时剖析报告：TRT FP16 逐层延迟与候选 batch1 基准

> 日期：2026-09-17 晚。协议中性测量（纯推理，不涉训练/验证选型/门判定）。GPU1（RTX 3090），TensorRT 11.3.0.99（`yolo26-trt`），引擎均在测量卡上重建。
> 目的：回答任务说明§8的警示——"参数变少但TensorRT不加速，只能算模型压缩，不能算推理优化"——用数据判定单元替换路线的延迟上限。

## 1. L0 教师逐层延迟剖析（batch1，fp16 strongly-typed，100轮）

引擎级逐层 GPU 时间合计 2.154 ms/轮（wall ≈2.9ms，差值为 memcpy/launch 开销）。关键份额：

| 区块 | 延迟份额 | 对照其MACs份额 |
|---|---:|---:|
| Detect头卷积 + end2end解码核 | **34.8%**（16.4%卷积 + 18.4%解码） | 38.7% |
| 高层backbone（L5-L10） | 15.7% | ~14% |
| 高层neck（L13/L23-L28） | 14.0% | ~13% |
| **被替换的4层（L5/L7/L23/L26）** | **2.20%** | 8.4% |
| ACFRConcat（L18） | 8.3%（访存受限的160×160门控卷积） | 3.8% |

## 2. 候选 batch1 端到端延迟（冻结100图协议、预热48、10次轮换）

| 对比 | L0 ms/图 | 候选 ms/图 | Δ | 解读 |
|---|---|---|---|---|
| vs P-N（neck DWConv） | 2.224 | 2.245 | **+0.94%** | 噪声级——省2%延迟份额换不来净收益 |
| vs U2（GhostConv全FP16） | 2.275 | 2.306 | **+1.38%** | 噪声级偏慢 |
| vs U1（DWConv混合精度） | 2.181 | 2.391 | **+9.62% 显著变慢** | L7的FP32节点+双Cast的税远超省下的量 |

## 3. 结论（并入A/B裁决材料）

1. **单元替换路线的延迟上限被封死**：被换4层只占TRT batch1延迟的2.20%——即便U1/U2精度门全过，延迟改善上限≈2%，远低于S0要求的≥8%延迟目标。实测三个候选全部持平或更慢（U1混合精度因FP32节点+Cast反而+9.6%）。**"压缩≠加速"在本文架构上成立**：参数/GMACs的下降集中在访存受限、非瓶颈的层。
2. **Detect头结论修正为诚实版本**：其延迟份额34.8%与MACs份额38.7%大致成比例，且其中18.4%是end2end解码核（TopK/Gather链，头瘦身动不到）——"最大的免费午餐"实际是"按比例的午餐+一半在禁区"。
3. **B路线的延迟论证**：宽度收缩作用于高层backbone+neck合计~30%的延迟份额——×0.8宽度理论延迟收益约10%，是唯一能同时满足压缩门与延迟目标的已识别路径（与§2方向一的参数/GMACs论证独立地收敛）。
4. ACFR的L18延迟份额8.3%（>其MACs份额3.8%）：门控在160×160上的1×1/3×3卷积访存受限。第四章冻结证据为引擎级batch1平价（-0.48%），不构成矛盾；此处仅作为论文"讨论"小节数据点记录，不改变任何已封箱结论。
