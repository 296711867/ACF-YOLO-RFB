# Phase 2 官方 P2 640/960 配对 50 epoch 分辨率报告

> 工作包：`P2-RESOLUTION-SCREEN`  
> 日期：2026-07-29（Asia/Shanghai）  
> 结论：960 在短跑中全面提升；后续完整训练因计算成本在39/200人工终止，不再恢复，P2-640保持论文主模型。

## 1. 配对公平性

- 官方 YOLO26n-P2、原生损失、同一 `yolo26n.pt`、固定 BDD100K 400/100 子集。
- 两组均为 50 epoch、batch 16、nbs 64、seed 0、GPU0、相同优化器与增强。
- 配置差异严格只有 `imgsz`（640/960）和 run name。
- 两组均完成 50/50 epoch，无 early stopping、自动恢复、OOM、NaN 或 Inf。

## 2. Ultralytics 指标与成本

| 指标 | P2-640 | P2-960 | 变化 |
|---|---:|---:|---:|
| 最佳 epoch | 49 | 40 | — |
| Precision | 0.51416 | 0.56673 | +0.05257 |
| Recall | 0.15348 | 0.18381 | +0.03033 |
| mAP50 | 0.13472 | 0.18336 | +0.04864 |
| mAP50-95 | 0.06343 | 0.09377 | +0.03034（+47.83%） |
| 50 epoch 有效时间 | 194.74 s | 401.13 s | +105.98% |
| 参数量 | 2,518,352 | 2,518,352 | 不变 |
| GFLOPs | 7.54 | 16.97 | +125.0% |

独立验证 mAP50-95 分别约为 0.0634 和 0.0935，与 CSV 最佳点一致。监控采样显存约为 640 的 7.8 GB、960 的 13.6 GB；960 smoke 最高日志显存约 14.7 GB。独立 val 的单图推理日志约 5.1/5.2 ms，受短数据集和 batch 吞吐影响较大，不作为正式部署延迟结论。

## 4. 判定

P2-960 通过短跑候选门槛，但代价约为2.25倍计算量和2.06倍短跑训练时间。后续完整训练实测约22.68分钟/epoch，并在39/200由用户人工终止；当前best mAP50-95为0.28507。项目决定不恢复200 epoch，P2-640保持论文主模型；960只作为分辨率与计算预算分析，并补充一次epoch39完整10k尺寸评估。
