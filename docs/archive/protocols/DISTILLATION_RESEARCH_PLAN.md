# YOLO26 P2到P3小目标蒸馏研究计划

> 冻结日期：2026-08-05（Asia/Shanghai）
> 状态：Phase 4 Stage20已完成且未通过预注册门；路线关闭
> 原则：只开展这一条新路线；先工程验收和完整数据阶段门，不因小子集短跑结果直接长训

## 1. 研究问题与目标

BDD100K完整实验已经证明，官方YOLO26n-P2-640相对原生YOLO26n-640的all AP提高5.01%、small AP提高14.32%、small AR提高23.62%，但GFLOPs增加29.3%、训练时间约为2.05倍。冻结误差分析还显示P2在固定阈值下修复6,010个small漏检，同时新增12,948个未匹配预测。新研究不再继续堆叠注意力、IoU损失或特征融合模块，而是回答：

> 能否在训练阶段把P2教师的高分辨率小目标知识转移到原生P3/P4/P5学生，使学生在不增加推理参数和GFLOPs的前提下提高small AP/AR？

教师固定为已经完整训练的官方YOLO26n-P2-640 `best.pt`，SHA256为`f1a8ad980cdaf949a12ac98514b3ccc583e1026fe4b09aa664e8d2589bc2826c`。学生固定为原生YOLO26n-640，从与历史基线相同的COCO `yolo26n.pt`初始化。不得恢复P2-960充当主教师，也不得重新训练教师。

## 2. 文献依据与原创边界

ScaleKD针对小目标提出尺度解耦特征蒸馏与跨尺度助手[@zhu2023scalekd]；FGD指出检测蒸馏需要区分前景、背景和空间/通道重要性[@yang2022fgd]；CrossKD通过跨检测头路径缓解GT监督与教师目标冲突[@wang2024crosskd]；MSAD研究高分辨率教师到低分辨率学生的特征对齐[@qi2021msad]；QueryDet则表明只在必要位置使用高分辨率特征可以改善小目标的精度-成本关系[@yang2022querydet]。

因此，下列内容本身不得宣称原创：知识蒸馏、前景掩码、跨尺度对齐、高低分辨率教师-学生或稀疏高分辨率计算。拟研究的原创点只限定为以下YOLO26特定机制及其受控验证：

1. 将P2教师额外的stride-4特征下采样后与教师P3拼接，构成监督原生学生P3的跨层目标。
2. 使用真实GT面积构造连续small权重，而不是对所有位置等权模仿。
3. 使用YOLO26 one-to-many与one-to-one双分支在同一类别位置上的联合置信度，降低教师新增误检对学生的影响。
4. 蒸馏适配器只在训练期存在，最终推理模型严格恢复为原生YOLO26n结构。

只有当完整训练、多seed和消融均支持上述机制时，才允许将其写成有效原创方法。若只有普通蒸馏基线有效，只能报告“蒸馏应用收益”；若完整候选失败，则保留为负结果，不包装成最终创新。

## 3. 现有接口缺口

上游`DistillationModel`已支持冻结教师、特征hook、score-weighted L2、checkpoint恢复以及YOLO26端到端双分支，但默认使用学生检测头的层号同时hook教师。原生学生检测层输入为`[16, 19, 22]`，检测头为23；P2教师输入为`[19, 22, 25, 28]`，检测头为29。直接传入P2教师会错误hook，不能作为合法实验。

新实现必须显式分离层映射：

| 语义层 | P2教师层 | 原生学生层 | 蒸馏用途 |
|---|---:|---:|---|
| P2/4 | 19 | 无 | 下采样后并入P3教师目标 |
| P3/8 | 22 | 16 | 主要small蒸馏层 |
| P4/16 | 25 | 19 | 普通同尺度辅助蒸馏 |
| P5/32 | 28 | 22 | 普通同尺度辅助蒸馏 |
| Detect | 29 | 23 | 提取教师双分支可靠性，不做层号共用 |

实现最终复用了上游现有`DistillationModel`的教师冻结、hook、EMA/resume和checkpoint剥离所有权，在同一模块内扩展异构层映射，避免另建一套重复生命周期。没有并入CrossKD、FGD或其他外部仓库代码。

## 4. 拟议损失

记教师特征为`T2,T3,T4,T5`，学生为`S3,S4,S5`。P3跨层教师目标冻结为：

```text
T3_bridge = concat(avg_pool_2x(T2), T3)
S3_projected = projector_3(S3)
```

这种设计只训练学生侧投影器，避免训练教师目标变换器后与学生共同塌缩。P4/P5分别使用独立学生投影器对齐`T4/T5`。所有特征先按通道归一化，再计算加权误差。

small空间权重由当前增强后GT框生成。对面积`A`（640参考像素²）使用连续权重`exp(-A/1024)`，将框投影到P3网格并向外扩一格；多个框取逐位置最大值。该权重在实现测试中必须满足：面积越小权重越大、640/960参考映射一致、空GT图像仍产生有限损失。

教师可靠性使用两个端到端训练分支同类别概率的几何均值：

```text
Q_l = max_class sqrt(sigmoid(Z_one2many_l) * sigmoid(Z_one2one_l))
W3 = rho + (1 - rho) * M_small * max(avg_pool_2x(Q2), Q3)
```

其中`rho`是固定背景下限，防止只模仿GT框内部。最终损失为P3主损失加低权重P4/P5辅助损失。全路线只允许一个总蒸馏权重；该值只根据训练初始损失量级和梯度有限性在工程smoke中冻结，不得根据验证AP网格搜索。

## 5. 工程验收

在任何完整数据精度实验前，必须完成：

1. 教师/学生层映射、shape、空标签、混合尺寸GT和确定性权重单元测试。
2. 教师参数全冻结且无梯度；学生与投影器梯度有限；one-to-many/one-to-one均被读取。
3. CPU FP32、RTX 3090 CUDA/AMP、序列化、best/last保存和外部student checkpoint重载。
4. 保存后checkpoint中最终推理模型只含原生学生，不含教师和训练期投影器；参数量、GFLOPs和stride与原生YOLO26n一致。
5. 固定BDD 400/100子集3 epoch只检查工程健康，不作精度筛选。
6. 显存预检从batch16/nbs64开始；若候选OOM，control与全部候选统一降batch并使用新run名称，禁止只给候选降batch。

工程阶段禁止启动200 epoch，也禁止依据400/100指标选择损失权重。

## 6. 完整数据实验矩阵

全部组使用BDD 70k/10k、640、相同COCO初始化、相同实际batch/nbs、seed0和200-epoch学习率计划，在epoch20保存完整状态后强制暂停。

| 组别 | 内容 | 目的 |
|---|---|---|
| D0 | 原生YOLO26n同协议control | 排除batch、调度和新代码路径影响 |
| D1 | 显式映射P3/P4/P5的上游等价score-weighted KD | 普通知识蒸馏基线 |
| D2 | D1 + P2到P3跨层目标 + 连续small掩码 | 验证高分辨率小目标知识转移 |
| D3 | D2 + 双分支联合置信度 | 完整拟议方法，抑制教师错误 |

四组之外不增加注意力、NWD、SDD、DWF、类别权重、960输入或新数据增强。D3若未通过阶段门，不继续修改阈值或追加模块。D3通过后，D1/D2即构成主要消融；必要时只允许增加一次“D3去除small掩码”的完整数据Stage20消融。

## 7. 阶段门与停止规则

每个阶段都使用完整10k独立验证和尺寸评估。D2/D3相对D0必须同时满足：

- small AP相对提升至少5%；
- small AR为正提升；
- all AP相对下降不超过2%；
- medium/large AP不出现超过5%的明显退化；
- 推理参数、GFLOPs和输出stride与D0一致；
- 无OOM、NaN、Inf、自动恢复、教师梯度或checkpoint剥离错误。

顺序固定为：

```text
工程测试/3 epoch smoke
  -> 完整数据D0-D3 Stage20
  -> 仅保留门内最优候选恢复至Stage40
  -> Stage60
  -> 再决定是否完成200 epoch
  -> 完整10k独立/尺寸/分类别评估
  -> 最终候选和同协议control补seed1/seed2
```

Stage20、40或60任一核心门失败即停止该候选。短阶段通过不构成论文最终结论；完整200轮若收益消失，必须像通道注意力一样淘汰。

## 8. 资源与论文判定

教师前向会提高训练显存和时间，但不增加最终推理成本。实际资源只在batch预检后记录，不提前承诺。只使用空闲GPU0，不抢占GPU1外部任务。所有训练通过受控启动器和独立tmux运行，教师、配置、代码和输出均记录SHA256。

若D3完成200轮并通过多seed与消融，论文贡献可表述为“面向YOLO26端到端双分支的P2到P3小目标跨层蒸馏方法”。若D3只在seed0或短阶段有效，表述必须降级；若失败，论文恢复现有高分辨率特征实证研究定位，不继续无限试错。

VisDrone test-dev保持永久封存。方法冻结前不在VisDrone上调参；是否进行新的VisDrone train/val验证，必须在BDD最终结果后另行决策，且永不重新访问test-dev。
