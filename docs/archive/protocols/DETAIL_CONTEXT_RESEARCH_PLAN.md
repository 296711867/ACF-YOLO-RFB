# YOLO26-P2残差细节-上下文注入研究计划

> 冻结日期：2026-08-06（Asia/Shanghai）  
> 状态：Stage20已完成且未通过；路线关闭
> 工作包：`P5-RDCI`（Residual Detail-Context Injection）

## 1. 研究动机

BDD100K完整实验已经证明官方YOLO26n-P2-640相对原生YOLO26n-640的all AP和small AP分别提高5.01%和14.32%，说明stride-4检测层有效；但SDD、DWF、SA-NWD、浅层通道注意力和P2到P3蒸馏均未通过最终保留门。现有失败结果分别排除了替换下采样、复杂动态融合、定位损失重加权、通道重标定和训练期跨层蒸馏，不能继续组合这些候选。

DCAS在YOLOv8上通过最低层特征注入、上下文聚合和截断高层结构改善小目标检测，并在其公开BDD100K实验中报告mAP50-95从34.7%提高到36.8%[@yang2026dcas]。其官方代码以GPL-3.0发布，但实现会在模型构造时扫描硬编码数据目录，并同时删除P5、改写整个颈部和检测尺度，不能作为本项目的公平单变量直接移植。

本工作包只吸收“最低层细节有助于小目标”的文献动机，研究以下更窄的问题：

> 在保持官方YOLO26-P2四检测尺度、颈部拓扑和预训练迁移不变时，能否把P1细节与局部上下文以恒等残差方式注入P2，从而稳定提高small AP和small AR？

## 2. 冻结方法

模块输入为P2融合位置的top-down特征`H2`、backbone P2特征`B2`和backbone P1特征`B1`。首先把`B1`以2倍平均池化和`1x1 Conv-BN-SiLU`对齐到P2分辨率与通道，记为`A1`。随后使用固定`3x3`平均池化拆分局部上下文与高频细节：

```text
C1 = AvgPool3x3(A1)
D1 = A1 - C1
R2 = Conv1x1(concat(D1, C1))
B2' = B2 + R2
output = concat(H2, B2')
```

生成`R2`的最后一层卷积权重和偏置严格初始化为零，因此初始`B2' = B2`，整个候选在数值上等于官方P2 concat。新增支路只负责P1到P2的细节/上下文残差，不替换nearest上采样、官方P2特征、C3k2、Detect或原生YOLO26双分支损失。

唯一冻结版本不增加注意力、动态采样、可学习尺度权重、可调膨胀率或额外损失。平均池化核、注入位置和残差初始化不根据验证集搜索。

## 3. 原创边界

下列内容不是本文原创：特征金字塔、P2检测头、浅层特征注入、上下文聚合、平均池化和残差学习。DCAS的最低层注入与动态上下文思想必须明确引用，不能把其整体方法改名为本文模块。

拟验证的自研点仅限：

1. 面向YOLO26端到端P2结构，在原官方concat位置同时读取P1/P2/top-down三路特征而不改变后续层号和张量形状。
2. 将P1对齐特征显式拆成高频细节残差与局部上下文，并只向P2支路做零初始化残差注入。
3. 保持官方P2预训练迁移和四尺度推理路径，在同预算control、完整尺寸评估和最终多seed下验证收益。

只有完整训练、消融和多seed均支持时，才能将RDCI写成有效自研模块。工程通过、短跑提升或单seed Stage20提升都不构成最终有效结论。

## 4. 工程验收

在任何完整数据精度实验前必须满足：

1. 初始输出与普通concat严格相等；输入shape错误必须显式失败。
2. P1、P2、top-down和模块参数梯度有限；第二个优化步骤后对齐支路获得非零梯度。
3. CPU FP32、CUDA AMP、序列化、YAML构建、stride和外部checkpoint重载通过。
4. 模型仍输出P2/P3/P4/P5，参数和GFLOPs增量完整记录。
5. 从同一`yolo26n.pt`加载时，官方P2已有参数的迁移数量不得下降。
6. 固定BDD 400/100、640、3 epoch smoke只检查训练健康，不作精度筛选。

## 5. 精度实验与停止门

完整BDD使用70k/10k、640、相同COCO初始化、相同batch/nbs、seed0和200轮学习率计划。官方P2 control与P2+RDCI均在epoch20保存完整状态后强制暂停，执行完整10k独立验证和尺寸评估。

RDCI相对同协议官方P2必须同时满足：

- small AP相对提升至少5%；
- small AR为正提升；
- all AP相对下降不超过2%；
- medium/large AP退化均不超过5%；
- 无OOM、NaN、Inf、自动恢复或checkpoint异常。

Stage20失败即关闭，不搜索池化核、残差权重、分支宽度或其他注入位置。Stage20通过后依次恢复至Stage40和Stage60；完整200轮通过后补seed1/seed2，并增加一个去除细节拆分的同预算消融，证明收益不是普通P1投影造成。

## 6. 开源复用边界

- DCAS论文与官方仓库只用于设计依据和实现审计；不复制其`DSPPF`、数据扫描代码或网络YAML。
- 实现复用本项目已有PyTorch、Ultralytics解析器、受控训练器和尺寸评估链。
- VisDrone test-dev继续永久封存；RDCI冻结和BDD结论完成前不在VisDrone上选择模型或参数。

## 7. 工程验收结果

RDCI工程实现提交为`b71d23f`，smoke重试配置提交为`9a75721`，batch64预检提交为`ef02ca3`。

- 模块级恒等、两步梯度、shape拒绝、序列化、模型YAML和真实RTX 3090 CUDA/FP16反向通过。
- 加载官方P2全部状态后，初始最终预测逐元素一致；COCO权重迁移360/910项，不低于官方P2的360项。
- BDD 10类参数从2,518,352增至2,527,760（+9,408，+0.37%）；GFLOPs从7.540增至8.026（+6.44%）。
- 首次smoke在首批前因工作树缺少AMP本地资产而人工停止并保留失败元数据；未混入正式重试。
- 最终3 epoch smoke完成，日志峰值14.1 GB，无OOM、NaN或Inf；小子集AP近零在epoch2/3各触发一次内置fitness恢复。best内RDCI残差权重绝对均值为`6.27e-4`，证明支路参与学习。
- batch64固定子集1 epoch预检完成，日志峰值21.8 GB。考虑历史完整BDD比固定子集增加约1.6 GB，两组Stage20统一冻结batch32/nbs64，不在运行中自动降batch。

完整准备报告见`results/reports/original-methods/rdci_prep_report.md`。上述结果只允许进入R0/R1公平Stage20，不构成精度有效性证据。

## 8. Stage20结果与最终决策

R0官方P2与R1 RDCI均完成epoch20并保存完整可恢复状态。完整10k尺寸评估中，R1相对R0的all/small/medium/large AP分别变化+1.20%/+1.30%/+1.11%/+1.03%，small AR变化-0.56%。训练健康，但small AP至少+5%和small AR正提升两项核心门失败。

RDCI按预注册规则关闭，不进入Stage40、Stage60、200轮、多seed或追加消融，也不搜索池化核、残差权重、分支宽度和注入位置。完整报告：`results/reports/original-methods/rdci_stage20_report.md`；机器结果与哈希：`results/rdci-stage20/`。
