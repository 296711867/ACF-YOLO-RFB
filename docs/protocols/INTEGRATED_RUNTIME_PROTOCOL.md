# 自适应分辨率路由集成运行时协议

> 冻结日期：2026-08-08（Asia/Shanghai）
> 性质：性能补充证据，不改变正式10k精度判定，不用于模型选择

## 1. 比较对象

使用同一个BDD完整训练官方YOLO26n-P2-640 checkpoint，比较：

1. `full_640`：全部图只执行640推理。
2. `full_960`：全部图只执行960推理。
3. `random_25`：全部图先640，哈希随机Top25%再960。
4. `heuristic_25`：全部图先640，按原图像素small框置信度和Top25%再960。
5. `learned_25`：全部图先640，冻结P2第19层四分带路由头Top25%再960。

三个路由策略均把960结果替换回完整粗检结果列表。学习头直接在640前向hook中运行，不读取离线特征；最终选图成员集合哈希必须与冻结`val-seed0-scores.jsonl`一致，集合内得分顺序不参与哈希。

## 2. 固定输入

- 图像：`configs/eval/pgsr-final-val-10000.txt`前500张，顺序不变。
- 用途：只测运行时，不计算精度，不据此选择路由参数。
- 路由预算：25%，即精确125张。
- 输入分辨率：640或960；`conf=0.001`；`max_det=300`。
- batch：脚本显式切分为16；FP32；单张RTX 3090；单进程；相同模型实例。
- 模型与路由checkpoint SHA256由输出JSON自动记录。

## 3. 计时与显存

- 模型加载不计时。
- 每种完整策略先以16张图独立预热一次，预热不计时。
- 正式执行3次；五种策略每次循环轮换起点，降低固定顺序、温度和缓存偏差。
- 每个阶段前后执行CUDA同步。
- 总时间从输入路径进入640/960策略开始，到完整CPU Ultralytics Results列表以流式批推理物化并完成路由替换为止。
- 分别记录640粗检、路由计算、960复检、总时间、吞吐、峰值allocated显存和峰值reserved显存。
- 报告3次原始值、均值和样本标准差。

## 4. 判定边界

- 学习路由只有在平均总时间低于`full_960`时，才能声称在本服务器和batch16下形成端到端速度优势。
- 若与`full_960`接近或更慢，只能表述为固定25%复检预算下的精度研究。
- 单服务器500图结果不是跨硬件部署结论，不外推到边缘设备。
- 无论运行时结果如何，学习路由small AP点估计未超过启发式的正式精度判定保持不变。
