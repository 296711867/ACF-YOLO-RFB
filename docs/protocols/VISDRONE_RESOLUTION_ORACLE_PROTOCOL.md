# VisDrone分辨率路由外部上限协议

> 工作包：P13-VISDRONE-RESOLUTION-ORACLE  
> 冻结日期：2026-08-08（Asia/Shanghai）  
> 状态：推理前冻结

## 1. 问题与证据等级

本工作包只回答一个问题：在不同于BDD100K的高密度无人机场景中，同一冻结检测器从640提升到960后，是否存在足够且可集中选择的小目标收益，使新的自适应分辨率方法值得继续研究。

VisDrone val曾用于该数据集内部的模型选择，因此本结果是“跨数据集假设开发证据”，不是未见测试集上的最终外部验证。GT Oracle读取标签，只表示上限，不是可部署方法。永久封存的VisDrone test-dev不得访问。

## 2. 冻结输入

- 数据：`configs/data/visdrone.yaml`的548张val图像及现有YOLO标签。
- 模型：VisDrone原生YOLO26n seed0、100 epoch冻结`best.pt`。
- checkpoint SHA256：`8c9deeca9eff76a5461dd4567d5544c527b9d57546140a08b0dcba979176583c`。
- 类别：VisDrone原始10类，不使用BDD类别映射。
- 推理：FP32、物理GPU0、`conf=0.001`、`iou=0.7`、`max_det=300`、batch16。
- 唯一变量：`imgsz=640`与`imgsz=960`。
- 指标：现有COCO 101点尺寸AP/AR，IoU 0.50:0.95；面积按原图像素计算。

两组预测必须图像顺序完全一致，并保存逐图JSONL、参数和SHA256。不得训练、融合权重、改变阈值或搜索其他分辨率。

## 3. Oracle

逐图效用固定为960相对640在small GT上的额外类别匹配数，对IoU 0.50:0.95十个阈值求和。按效用降序、原始图像顺序稳定打破并列，精确选择`ceil(0.25 * 548) = 137`张使用960预测，其余使用640预测。

同时报告效用为正、零、负的图像数、全640、全960和25% Oracle的all/small AP与AR。50%预算仅可作为描述性曲线点，不参与是否继续的裁决。

## 4. 预注册继续门

必须同时满足以下条件，P13才通过：

1. 全960相对全640的small AP相对提升至少5%，small AR严格为正提升；
2. 全960的all AP相对下降不超过2%；
3. 25% Oracle的small AP与small AR均高于全640；
4. 25% Oracle至少保留全960相对全640的50% small AP绝对增量；
5. 25% Oracle的all AP相对全640下降不超过2%。

任一条件失败则停止该外部自适应分辨率路线，不训练新路由器。通过只允许进入新的、单独预注册的可学习方法工作包，不代表方法有效或已完成外部验证。

## 5. 禁止事项

- 不读取、推理或重新汇总VisDrone test-dev；
- 不根据结果修改预算、阈值、输入尺寸、checkpoint或效用定义后重测；
- 不把VisDrone val写成未参与历史选择的独立测试集；
- 不把GT Oracle、全960或现有YOLO26n写成本文原创方法；
- 不在本工作包中训练路由器或检测器。
