# 透视分带自适应分辨率路由正式协议

> 状态：正式10k val已按冻结设计完成；比较门未通过
> 冻结日期：2026-08-07（Asia/Shanghai）

## 1. 方法与原创边界

检测器固定为已验收官方YOLO26n-P2 e200权重，不更新任何检测参数。自研模块为8,769参数的透视分带分辨率路由头：读取640粗检的第19层P2/4特征（32通道），沿垂直方向固定分为4带，每带计算通道均值和最大值，拼成256维描述符，经`LayerNorm -> Linear(256,32) -> SiLU -> Linear(32,1)`输出960复检价值分数。

所有图先执行一次640检测；在一个固定评估集合内，仅将路由分数最高的25%图像执行第二次960全图检测，并以960结果替换这些图的640结果。最终推理不读取GT。SAHI、切片、全图960和官方P2均不是原创；原创边界只限透视分带描述、学习式固定预算路由和640/960两阶段决策。

## 2. 冻结训练证据

- 路由训练集：BDD train哈希序列offset 500起的5,000图，与500图开发集重叠为0；清单SHA256 `015520e35731e4f55457d8d3cba2bfa1a04ca0bae6d3737c21c16cc275081a25`。
- 监督效用：同一P2权重的960相对640在每图small GT上的额外匹配数，累计IoU 0.50:0.95；GT只用于离线训练标签。
- 标签分布：正/零/负为2,978/504/1,518，范围-27至57。
- 损失：Oracle效用排名前25%为正类的加权BCE；内部前4,000图拟合、后1,000图早停。
- 主checkpoint：seed0，最佳epoch15，SHA256 `544a3f47997bac89a44c7dc084f3a9137dbb9c09eedb10c446757372dbc0d7cf`。
- seed1/2只作开发稳定性，不用于选择主checkpoint。

## 4. 正式10k val一次性协议

1. 对BDD val全部10,000图生成固定清单，不读取标签训练或改路由头。
2. 使用同一官方P2权重分别生成全图640和全图960原始预测。
3. 只从640第19层提取4带描述符，用冻结seed0 checkpoint打分。
4. 固定路由分数Top 25%的2,500图使用960预测，其余使用640预测。
5. 同时计算全640、全960、哈希随机25%和粗检启发式25%；GT Oracle只可在结果解释中作为上限，不参与模型输出。
6. 不根据正式val结果更换seed、阈值、特征层、分带数、隐藏宽度、训练损失或路由预算。

正式保留门必须全部满足：

- 学习路由相对全640的small AP至少+5%；
- small AR必须正提升；
- all AP相对下降不超过2%；
- 学习路由的small AP和small AR均严格高于粗检启发式与哈希随机25%。

任一失败则模块不能写成有效最终方法，也不允许在val上修正后重测。

## 5. 计算边界

以像素面积近似检测计算，所有图一次640加25%图一次960，相对单次640为`1 + 0.25 * (960/640)^2 = 1.5625`倍；相对所有图直接960的2.25倍，减少约30.56%。正式报告还需记录实测端到端时间，不能只报告理论比例。

## 6. 冻结后正式判定

提交`da998af`后完成唯一正式10k val。学习路由相对全640的all AP、small AP和small AR分别变化+4.31%、+13.75%和+8.76%，基础门通过；但small AP 0.115461低于粗检启发式0.116185，违反第4节的严格比较门。协议判定为不保留，不修改本文件前述门槛，也不基于val更换seed后重测。完整结果见`results/reports/original-methods/perspective_router_final_report.md`。
