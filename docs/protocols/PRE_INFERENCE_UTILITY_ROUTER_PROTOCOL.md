# 检测前效用排序分辨率路由协议

> 工作包：`P12-PRE-INFERENCE-UTILITY-ROUTER`
> 冻结日期：2026-08-08（Asia/Shanghai）
> 当前授权：工程实现、BDD train/dev缓存、三seed低成本筛选；不得访问BDD正式val或VisDrone test-dev

## 1. 问题与目标

历史透视分带路由必须先完成所有图像的640检测，再把25%图像重复送入960检测。正式500图集成基准中，学习路由平均耗时3.7802秒，比全960的3.6136秒慢4.61%。其训练还把连续效用压成Oracle前25%二分类标签，使用加权BCE，与最终固定预算下的效用排序不完全一致。

P12将决策前移到检测器之前。路由器只读取低成本RGB缩略图，先选择每张图像的唯一输入分辨率，再把图像互斥分配到640或960批次。任何图像都不得同时执行640和960检测。目标是在保留固定25%高分辨率预算的同时，同时满足：

1. 学习分数比同成本图像统计启发式捕获更多960相对640的小目标效用；
2. 最终检测指标相对全640改善；
3. 端到端运行时间低于全960；
4. 方法能在未参与BDD设计的独立数据协议上复查。

## 2. 相关工作与原创边界

RANet已在分类中使用低分辨率子网与高分辨率路径实现样本自适应推理[@yang2020ranet]；Uzkent等已使用强化学习在检测前选择高低空间分辨率[@uzkent2020efficient]；AutoFocus只对粗尺度预测出的small候选区域执行细尺度检测[@najibi2019autofocus]；DynamicDet使用多尺度特征路由和检测损失设计动态检测器[@lin2023dynamicdet]；DualRes进一步强调动态检测的ONNX部署与实际速度验证[@elhassani2026dualres]。

因此，检测前分辨率选择、动态网络、固定预算和高分辨率小目标检测本身均不属于本文原创。P12拟验证的具体组合边界仅为：

- 以冻结640/960预测产生的连续small检测效用监督缩略图路由；
- 以效用差加权的成对排序直接对齐精确Top25%预算；
- 以道路透视分带与全局缩略图特征联合打分；
- 检测器无关的640/960互斥批处理与跨数据迁移协议；
- 同成本启发式、学习统计基线和实际端到端运行时的完整比较。

只有全部正式停止门通过后，以上组合才能称为有效方法。工程实现或BDD开发集正结果不构成论文创新结论。

## 4. 缩略图与模型

- 输入：RGB，固定`160×96`，OpenCV `INTER_AREA`缩放，像素除以255。
- 不读取GT、检测输出、P2特征、天气标签或相机元数据。
- 卷积干路：三次stride-2卷积，通道`3→16→24→32`，后两层使用深度可分离卷积。
- 描述子：最终`32×12×20`特征的四个垂直分带均值/最大值，加全局均值/最大值。
- 路由头：`LayerNorm → Linear(320,64) → SiLU → Linear(64,1)`。
- 参数上限：100,000；不根据开发结果增加宽度或深度。

## 5. 训练目标

每张图连续效用为`u_i`，路由分数为`s_i`。主损失固定为：

```text
L = L_rank + 0.25 * L_reg
```

`L_rank`对batch内所有效用不相等的样本对计算：

```text
softplus(-sign(u_i-u_j) * (s_i-s_j))
```

每对样本按`|u_i-u_j|`相对batch非零平均差加权，权重上限为4。`L_reg`是分数与训练集全局标准化效用之间的Smooth L1。训练集效用均值和标准差只从前4,000拟合图像计算并写入checkpoint。

固定优化设置：AdamW、batch128、lr `1e-3`、weight decay `1e-4`、最多100 epoch、patience15、seed 0/1/2。早停键依次为内部holdout的utility capture和loss。开发集不参与epoch选择。

## 6. 同成本基线

在相同`160×96`缩略图上冻结以下分数：

1. 哈希随机分数；
2. 全局灰度标准差；
3. 全局Laplacian绝对响应均值；
4. 全局Sobel幅值均值；
5. 上半区域Laplacian响应；
6. 使用全部冻结图像统计量、只在前4,000拟合图训练的固定岭回归。

不得把需要完整640检测的small置信度启发式称为同成本基线；它只作为历史准确率参考。

## 7. P12开发停止门

三seed全部满足以下条件才进入互斥运行时和外部数据协议：

- 训练、holdout和开发分数全部有限，无数据缺失或图像解码失败；
- 参数不超过100,000；
- 三seed开发utility capture均高于最佳非神经图像统计基线；
- 三seed开发utility capture中位数至少比最佳非神经基线高5%；
- 三seed开发Top25%效用和均为正；
- seed间utility capture样本标准差不超过0.05；
- CPU/CUDA可用环境下前向、反向、序列化和固定Top25%选择一致。

若开发门失败，停止P12，不访问BDD正式val、不实现检测运行时、不改缩略图尺寸、预算、宽度或损失权重。

## 8. 后续正式门

开发门通过后，互斥执行和外部数据还必须满足：

- 学习路由端到端平均时间比全960低至少10%；
- small AP相对全640至少提高5%，small AR为正，all AP不低于-2%；
- 至少一个核心小目标指标高于同预算、同前置成本的最佳启发式；
- 外部正式结论不依赖BDD val二次选参；
- ONNX或等价部署运行时与PyTorch结论方向一致后，才声称部署效率。
